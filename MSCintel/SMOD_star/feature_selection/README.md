# Feature Selection and Stacking Model Pipeline

This document describes the feature-selection and model-construction stage of SMOD_star. Starting from calculated training and test feature CSV files, the pipeline performs correlation-based screening, resampling-based statistical screening, wrapper-based feature selection, and Stacking model training and evaluation.

## 1. Overview

The feature-selection workflow consists of five sequential steps:

```text
Correlation screening
        ↓
Significance screening
        ↓
Feature intersection
        ↓
Wrapper feature selection
        ↓
Stacking model training and evaluation
```

## 2. Required Input Files

Before running the feature-selection pipeline, prepare the training and test feature files generated by the feature generation pipeline.

### 2.1 Minimum Sample-Size Requirement

For statistically meaningful resampling-based screening, we recommend at least 10 positive and 10 negative non-redundant training sequences after sequence-identity filtering at 40%.

Smaller datasets may still run but can produce unstable feature-selection and cross-validation results.

### 2.2 Training and Test Feature Files

The training feature files should be placed in:

```text
outputs/features/train/
```

The test feature files should be placed in:

```text
outputs/features/test/
```

All `.csv` files in these folders will be automatically discovered and merged as feature files. Standard SMOD_star feature files are processed in a predefined order, while additional CSV feature files are processed afterward in alphabetical order.

Each feature CSV file must follow this format:

```text
AccessionName,feature_1,feature_2,...,feature_n,label
```

Requirements:

1. The first column must be `AccessionName`, and the last column must be `label`.
2. The `label` column must contain only binary values (`0` or `1`).
3. All feature columns must contain numeric values.
4. Within each dataset folder, all CSV files must contain the same `AccessionName` order and identical labels.
5. The training and test folders must contain matching feature CSV filenames.
6. Corresponding training and test CSV files must contain matching feature columns.

Custom feature categories are supported. To add a new category, place feature CSV files with the same filename and matching feature columns under both `outputs/features/train/` and `outputs/features/test/`.

> **Important:** Every `.csv` file in these directories is treated as a feature file. Do not place temporary files, summary tables, comparison reports, or unrelated CSV files in these folders.

## 3. Run the Pipeline

From the repository root, enter the `SMOD_star/` directory:

```bash
cd SMOD_star
```

Run the feature-selection and Stacking pipeline directly:

```bash
python feature_selection/pipeline.py --config config.yaml
```

Run the pipeline in the background:

```bash
nohup python feature_selection/pipeline.py --config config.yaml > feature_selection_pipeline.log 2>&1 &
```

## 4. Output Control

Intermediate and final output saving is controlled through the `feature_selection.save_outputs` settings in `config.yaml`.

Set an option to `false` to execute the corresponding stage without retaining its output files. The default settings can be used for normal execution.

## 5. Expected Outputs

After successful execution, the main results are saved under:

```text
outputs/feature_selection/
```

The principal output files are:

```text
outputs/feature_selection/model_metrics.csv
outputs/feature_selection/stacking_model/roc_curves.png
outputs/feature_selection/stacking_model/prc_curves.png
outputs/feature_selection/stacking_model/model/SMOD_∪_model.joblib
outputs/feature_selection/stacking_model/model/SMOD_star_model.joblib
outputs/feature_selection/stacking_model/model/SMOD_∩_model.joblib
```

`model_metrics.csv` summarizes the cross-validation and independent-test performance of the four base models and the three Stacking feature-set strategies.

The three `.joblib` files contain the fitted base models, meta-model, selected feature list, feature-set strategy, and prediction threshold for the corresponding Stacking model.
